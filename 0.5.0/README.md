# Лабораторна робота №5 — версія 0.5.0

## Опис проекту

Цей репозиторій містить версію `0.5.0`, яка реалізує клієнт-серверний SPA-застосунок з акцентом на безпеку даних. Фронтенд написано на TypeScript, бекенд — на Express.js, а база даних зберігається у `sql.js`.

## Архітектура системи

### Структура проекту
- **`index.html`** — сторінка-обгортка для клієнтської частини.
- **`app.ts`** — основний фронтенд-код: логіка авторизації, керування формами, відображення таблиць і захищені запити до API.
- **`apiClient.ts`** — HTTP-клієнт з таймаутами, обробкою помилок та передачею демо-ідентифікатора користувача.
- **`backend/src`** — серверна частина: маршрути, сервіси, репозиторії, middleware та ініціалізація бази даних.
- **`shared/dtos.ts`** — спільні типи даних для клієнта та сервера.

## Основні захисні механізми

- **Серверна валідація DTO** — перевірка даних перед створенням і оновленням записів.
- **Захист від SQL-ін'єкцій** — безпечний пошук за допомогою параметризованих SQL-запитів.
- **Захист від IDOR** — доступ до записів обмежено для неадміністраторів тільки власником запису.
- **Заголовки безпеки** — `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Cross-Origin-Opener-Policy`.
- **CORS whitelist** — дозволені запити тільки з `http://localhost:5173` та `http://127.0.0.1:5173`.
- **Безпечний рендеринг** — у фронтенді динамічні значення вставляються через DOM-елементи, а не через `innerHTML`.

## Запуск проекту

### Клієнтська частина
1. Перейдіть до папки `0.5.0`:
   ```bash
   cd "0.5.0"
   ```
2. Встановіть залежності:
   ```bash
   npm install
   ```
3. Зберіть TypeScript фронтенд:
   ```bash
   npm run build
   ```
4. Відкрийте `index.html` у браузері або запустіть локальний сервер.

> Після збірки буде створено `dist/app.js` і `dist/apiClient.js`, які підключає `index.html`.

### Серверна частина
1. Перейдіть до папки бекенду:
   ```bash
   cd "0.5.0/backend"
   ```
2. Встановіть залежності (якщо ще не зроблено):
   ```bash
   npm install
   ```
3. Запустіть сервер у режимі розробки:
   ```bash
   npm run dev
   ```
4. Або зберіть і запустіть у продакшн-режимі:
   ```bash
   npm run build
   npm run start
   ```

Сервер доступний за адресою `http://localhost:3000`.

## Опис API

### Ендпоінти для `software`
- `GET /api/v1/software` — перелік ПЗ.
- `GET /api/v1/software/search-unsafe?q=...` — демонстраційний небезпечний пошук для SQLi-перевірки.
- `GET /api/v1/software/search?q=...` — безпечний пошук по назві та коментарю.
- `GET /api/v1/software/:id` — отримати запис за ID (доступ адмінів та власника).
- `POST /api/v1/software` — створити запис (для автентифікованих користувачів).
- `PUT /api/v1/software/:id` — оновити запис (адмін або власник).
- `DELETE /api/v1/software/:id` — видалити запис (адмін або власник).

### Ендпоінти для `users`
- `GET /api/users` — перелік користувачів.
- `POST /api/users` — створити користувача.
- `PUT /api/users/:id` — оновити користувача.
- `DELETE /api/users/:id` — видалити користувача.

### Ендпоінти для `categories`
- `GET /api/categories` — перелік категорій.

## Приклади запитів

### Безпечний пошук ПЗ
```bash
curl "http://localhost:3000/api/v1/software/search?q=office"
```

### Демонстраційний уразливий SQLi-пошук
```bash
curl "http://localhost:3000/api/v1/software/search-unsafe?q=office' OR '1'='1"
```

### Отримати запис за ID
```bash
curl http://localhost:3000/api/v1/software/<id>
```

### Створити запис ПЗ
```bash
curl -X POST http://localhost:3000/api/v1/software \
  -H "Content-Type: application/json" \
  -H "X-Demo-UserId: <user-id>" \
  -d '{"name":"My App","version":"1.0","license":"MIT","seats":5,"categoryId":"1","comment":"Тестовий запис"}'
```

### Оновити запис ПЗ
```bash
curl -X PUT http://localhost:3000/api/v1/software/<id> \
  -H "Content-Type: application/json" \
  -H "X-Demo-UserId: <user-id>" \
  -d '{"version":"1.1","seats":10}'
```

### Видалити запис ПЗ
```bash
curl -X DELETE http://localhost:3000/api/v1/software/<id> \
  -H "X-Demo-UserId: <user-id>"
```

## Перевірка за чеклістом

- [x] CORS налаштовано на whitelist.
- [x] Додано HTTP-заголовки безпеки.
- [x] Пошук реалізовано з параметризованими SQL-запитами.
- [x] Додано демонстраційний уразливий SQLi-ендпойнт `search-unsafe`.

- [x] Повертається 403 `FORBIDDEN` при доступі до чужого запису, а не 404.
- [x] Демонстраційна авторизація виконується через заголовок `X-Demo-UserId`.
- [x] Фронтенд відображає дані через DOM-елементи, а не через вставку динамічного HTML.
- [x] README оновлено для `0.5.0` та описує поточні функціональні можливості.

## Безпека: було / стало

- Було: пошук міг бути вразливим до SQL-ін'єкції. Стало: `software.repository.ts` використовує параметризовані запити для `search`.
- Було: авторизація на читання/запис не перевіряла власника запису. Стало: `ensureSoftwareAccess` у `software.service.ts` повертає `403 FORBIDDEN` для чужого запису.
- Було: користувачі могли бачити будь-які дані без контексту. Стало: для створення, оновлення, видалення та отримання конкретного ПЗ потрібен заголовок `X-Demo-UserId`.
- Було: фронтенд міг синтетично створювати небезпечний HTML. Стало: динамічні значення обробляються через `textContent`/DOM-елементи.
